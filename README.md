# WorkBuddy 实战指南 · 把 AI 用进工程现场

一本写给 AI 小白的工程书：不讲模型原理，只讲怎么把 WorkBuddy 用成工位上的助手，把每天那些重复的、耗人的、容易漏的活，交给它先干一遍，你负责验收和签字。

## 谁适合读

- 制造业、汽车零部件、电子硬件行业的研发 / 质量 / 工艺 / 项目人员
- 用过 AI 聊天，但没让它真正碰过自己的文件和软件
- 想让 AI 干活，又怕它瞎编、怕它越权、怕出了事说不清是谁的责任

**不适合**：想读模型原理、想学提示词玄学、想找一个万能按钮的人。这本书里没有一个万能按钮。

## 全书的一句话主张

> AI 交回来的东西，你没验过，就不是你的。

全书所有场景都围绕这条展开：怎么把活说清，怎么让它干，怎么验收，怎么在它的产出上签你的名字。

## 每个场景都长一个样（八件套）

全书 72 个场景统一按这个结构写，翻到哪一页都能抄作业：

1. 一句话背景：这件事为什么烦
2. 名词小词典：本节出现的行话先说人话
3. 开工前准备：要备什么文件、开什么权限
4. 操作步骤：一步一步，每步都有明确产物
5. 可复制提示词：整段拿走就能用
6. 过程与判断点：哪一步必须停下来看一眼
7. 翻车清单：至少三条，写清症状和补救
8. 验收标准与变体：怎么算干完，至少给两种改法

可信度用三级标注，`★★★` 实测、`★★` 跑通、`★` 调研。没跑过的东西不会标成跑过。

## 自己动手构建

```bash
# 1. 只构建 HTML（纯标准库 Python，无需装依赖）
python 脚本/build_book.py

# 2. 渲染 PDF（需要 Node 与 Playwright）
NODE_PATH=<你的 playwright 模块目录> node 脚本/render.js pdf \
    成稿/WorkBuddy实战指南.html 成稿/WorkBuddy实战指南.pdf

# 3. 想让目录带上真实页码，跑两遍
python 脚本/extract_toc_pages.py 成稿/WorkBuddy实战指南.pdf   # 需要 PyMuPDF
python 脚本/build_book.py                                      # 第二遍注入页码
NODE_PATH=<你的 playwright 模块目录> node 脚本/render.js pdf \
    成稿/WorkBuddy实战指南.html 成稿/WorkBuddy实战指南.pdf
```

如果 Playwright 报浏览器找不到，用 `CHROME_PATH` 指到本机的 Chrome 可执行文件再跑 `render.js`。

改配图：`脚本/figlib.py` 里有 12 个版式模板（流程、对比、树、表格、循环、清单、分层、条形、卡片、步骤、终端、时间轴），改完跑对应章的 `gen_figs_chN.py` 即可重新出图。
